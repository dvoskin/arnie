## THE TRAPS THAT BIT THIS SESSION — ALL OF THEM COST A RUN

1. **A run that races an edit measures neither version.** Bit TWICE. Clear
   `__pycache__`, start the suite, then keep your hands off the tree.
2. **`git add core/ tests/` silently omits `handlers/`.** A broken import was
   pushed and the suites had passed against the working tree, not the commit.
   `git add -A`, then `git diff HEAD origin/<branch>` before believing a push.
3. **An AST gate that substring-matches is a grep trap in costume.** A mutation
   defeated one by aliasing an import. Assert STRUCTURE — ancestry, nesting —
   never spelling.
4. **A metric's denominator must be the population it claims.** One reported
   `16 of 15 (106.7%)` by dividing resolutions (interpretation time) by rows
   (settle time).
5. **SQL operator precedence.** `where user_id=26 and A or B` reported three
   other users' rows as Danny's.
6. **pytest here prints NO summary line.** Count progress characters:
   `.`=passed `s`=skipped `x`=xfail `F`=FAILED. Exit code alone is not enough.
7. **Verify a mutation LANDED before reading its result.** Count occurrences
   before and after the replace.
8. **An outage produces clean, confident zeros.** Two corpus runs died on API
   credits and reported a beautiful mix over a survivor set.
   `turns_reached_the_model` is the only reason they were not published.
9. ⛔ **A MATCHER THAT CANNOT FAIL MAKES ITS OWN LEFTOVER-DETECTOR USELESS.**
   `rows_the_corpus_did_not_predict = 0` read as "everything is explained"; it
   meant "the empty key matches everything". The reassuring value WAS the
   defect. Before trusting a zero, ask what would have to happen for the
   instrument to print a non-zero.
